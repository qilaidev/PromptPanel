# 关键模块审计修复记录 - 2026-06-09

## 背景

本轮审计聚焦生产稳定性，不做大范围重构。目标是修复两个后续容易出事故的关键风险：

- 词库导入失败时可能留下半导入状态。
- 快捷面板排序与数据层排序事实分叉，可能导致快捷编号漂移。

## 决策

### 1. 词库导入必须原子化

根因：`LibraryTransferService.importPayload` 过去通过仓储逐条写项目和词条。虽然写库前会创建备份，但中途失败仍可能导致部分项目已创建、部分词条未导入，用户需要手动恢复。

处理方式：

- 保留解析校验后、写库前手动备份，作为最终兜底。
- 导入写入阶段改为单个 SQLite 写事务。
- 任一项目或词条写入失败时，整个导入自动回滚。

验收标准：

- 成功导入时项目、词条和统计仍正确。
- 模拟词条插入失败时，前面已创建的项目也必须回滚。

### 2. 快捷面板排序回到核心规格

根因：数据层和文档规定 `sortOrder` 是置顶后的第一排序键，但 `QuickPanelViewModel.applyPanelRankingSort` 二次排序时忽略了 `sortOrder`，优先按使用次数排序。

处理方式：

- 快捷面板排序调整为：置顶优先、`sortOrder` 高优先、最近使用优先、使用次数优先、当前项目优先、`updatedAt DESC, id ASC` 收口。
- 保留二次排序函数，作为面板本地过滤后的稳定收口，不新增抽象。

验收标准：

- 手动设置了更高 `sortOrder` 的词条，即使使用次数更低，也应排在前面。
- 同权重词条继续通过 `updatedAt` 和 `id` 稳定收口，避免快捷编号随机漂移。

## 回滚方式

如导入事务改动引发未知问题，可回退本次代码变更；用户数据层面仍保留写库前备份。排序变更可单独回退 `QuickPanelViewModel.applyPanelRankingSort`，但需要同步更新文档，否则会再次出现规格分叉。
